# Know Engine RAG 重构实施与对比

对比基线为 `48b778053d55a056a5443dc55a22e4108fb11754`。旧实现以该提交的实际调用点为准。原计划文件为工作区中的 `RAG_MVC_REACTOR_REFACTOR_PLAN.md`。

## 从旧入口到新入口

旧版已经由 `ChatService` 显式调用意图识别、问题改写、检索、重排和低层模型。运行中的 RAG 没有经过 `RagChatService`、`DefaultRetrievalAugmentor` 或 `ProgressAwareContentRetriever`。仍存在的框架耦合主要在召回后的 `Content` 数据表示、聚合器的多 Query Map、引用元数据和 `DefaultContentInjector`。旧 `MemoryConfig` 配置的 Redis 记忆提供器也没有进入这条在线主链，在线已经直接读取 DB 历史。

新版保留 LangChain4j 的 OpenAI 兼容客户端、Embedding 客户端、提示词、消息类型和意图/标题的 AiServices 能力。重构的边界是由应用持有检索候选、上下文、轮次状态和 SSE 协议。这样取消、超时、终态与部分答案能在同一个 run 上协调，线上和评测也能共享业务输出。

```text
ChatController
  → ChatRunService 创建并启动轮次
  → ChatService 按 AUTO / RAG / COMMON 路由
  → RagRetrievalService 改写、版本快照、双路检索、RRF、重排和上下文
  → ChatModelGateway 读取模型事件
  → ChatRunStore 原子保存答案、引用和轮次状态
  → ChatController 输出已确认提交的 SSE end
```

## 逐项对照

| 维度 | 基线实际行为 | 现在的行为与取舍 |
| --- | --- | --- |
| Spring MVC、Reactor、LangChain4j | Spring MVC 把 Flux 适配为 SSE。LangChain4j 负责底层模型和部分检索数据表示。模型 HTTP 是阻塞读取。 | 技术栈和模型传输形态延续。领域层用命中、候选、上下文、模型事件等类型表达结果。Servlet 写出有独立有界执行器。 |
| AUTO、闲聊和知识问答 | AUTO 尝试用临时记忆做意图识别。旧入口给单一 ChatMemory 传自定义 MemoryId，LangChain4j 1.11.0 的这种配置会走到未初始化的记忆 Map 并触发 RAG 降级。 | AUTO 使用每轮独立的默认临时记忆，按分类结果在闲聊和知识问答之间分流。意图服务故障仍回落到 RAG。显式 RAG 和 COMMON 可跳过意图调用。RAG 使用原问题生成，改写结果用于检索和重排。 |
| 多轮记忆 | 主链按本轮消息 ID 读取一次 DB 历史，过滤空消息。旧缓存适配器还有按“最后两条”排除的实现。 | 同一次快照给意图、改写和生成。只使用新轮次的完整已完成问答，按对裁剪。旧 NULL 关联按相邻问答配对。意图分类仅写临时内存。Redis 继续服务其他模块。 |
| 生效版本和召回 | 两路共用一次 MySQL 生效版本查询，ES 按版本过滤。各路上限 10，KNN 阈值 0.5。 | 保留相同范围和上限，KNN 仍在 Top K 前过滤。请求保留实际 HTTP Cancellable，命中校验索引 ID 与业务 ID。范围失败直接终止，任一路成功即可继续，即使成功路为空。 |
| RRF 与分数解释 | 根据 Content 的 ES ID 判等合并候选，累加排名并合并来源。两路原始分经单字段传递。 | 用文档、版本和分块组成身份。每路去重，按 `1/(60+rank)` 累加并稳定排序。分开保存 BM25、向量分、两路名次、RRF 分和重排分。混合来源继续显示为 HYBRID。 |
| 百炼重排 | RRF 候选批量评分，重排失败或关闭时回落到 RRF。评分后的列表最多 10 条。 | 保留按候选索引回填和协议校验，最多评分 20 个候选。先按重排分再按 RRF 打破平局，父块去重前继续扫描候选。阈值默认关闭，启用后过滤为空会明确返回资料不足。 |
| 父块、预算和引用 | 重排后取父块填充，按父 ID 去重，最多 5 项。父块正文可能覆盖引用中的子块文本。 | 以版本化父块去重，只有实际选中的父块占一个槽。读取失败或放不下时回退子块。引用保留命中子块正文和实际注入上下文映射。32 KiB UTF-8 预算显式保留系统提示、完整历史、问题、资料、输出和安全余量。较长历史和资料可能比旧版更早裁剪。 |
| 资料不足 | 可继续向 RAG 模型发出带空资料的生成请求。 | 使用固定的本地回答，状态为 `COMPLETED/NO_EVIDENCE`。两路都不可用仍返回检索失败。空资料时回答措辞发生有意变化。 |
| 进度、SSE 和浏览器 | 前端解析字符串前缀。正常流结束后统一解除加载状态，模型文本可能撞上控制前缀。 | 新页面按命名 JSON 事件区分进度、资料、文本和终态。保留旧 API 兼容适配，添加停止、状态回查和失败部分文本。当前轮完成前再次请求同一会话会返回冲突。 |
| 完成、取消与超时 | 有有界池、HTTP 取消和超时保护，正常流结束时更新消息。没有按 run 查询终态，SDK 返回与明确完成没有充分区分。 | 在 OpenAI 兼容传输层校验 `[DONE]`，完成回调单独成事件。区分准备、首字、空闲和总期限。停止或断开后独立保存，后续状态可查。物理槽等底层工作退出才释放。 |
| 消息和恢复 | 用户消息与助手占位提前写入，成功时回填。失败时可能留下空助手占位。 | `chat_run` 加唯一幂等键和会话行锁，记录检查点、终态、原因和部分答案。终态用 token 条件更新，MySQL 确认后发 SSE end。启动将上个单实例残留轮次收敛为失败，保存已有检查点。 |
| 离线评测 | 走在线字符串流，先建临时会话和消息，解析前缀，再查回引用并清理临时数据。 | 消费同一 RAG 引擎的结构化结果，省去临时会话的创建、回查和删除。片段/父块匹配语义保留，LLM 评判使用真正注入的上下文。评测准入独立，仍和在线共享部分上游执行池。 |
| 数据与部署 | Windows Java，远程 MySQL/Redis/ES/SeaweedFS/MinerU，百炼 API。 | 新增聊天轮次表和消息关联列，旧消息、历史引用 JSON 和索引格式可继续读取。静态页面仍由本机 Java 提供。 |

## 注释接续

- `MemoryConfig` 与旧数据库记忆说明对应现在的 `DatabaseChatMemoryStore.loadHistory`、`ChatService.route` 和《记忆存储说明》。其中写清快照归属、按轮配对和临时意图记忆。
- `CommonChatService`、`RagChatService` 和 `ChatParam` 的职责对应 `ChatService.Request`、`answer`、`ChatModelGateway` 与 `ChatRunService.ActiveRun`。提示词差异、输入和输出契约、会话和两条消息 ID 的含义在实现位置说明。
- 旧聚合器、RRF、内容判等和引用工具的说明对应 `RagContext.fuse`、`RagContext.select` 与 `RagRetrievalService.rank`。公式、平滑常数、两路原分、重排索引对齐、排序和父块回退均在代码里解释。
- 旧 ProgressAware 包装器的说明对应 `ChatService.execute`、`RagRetrievalService.prepare` 和 `ChatController`。进度从真实阶段发出，API 适配负责编码，前端按文档和版本去重显示引用。

## 性能和质量的判断边界

在线增加了创建请求、轮次记录、检查点和终态确认，代价是更多 HTTP 与 MySQL 往返。检查点和最终写入各用一条带条件的 InnoDB 多表更新，减少远程数据库往返。独立收尾连接和有界写出池提供资源隔离。评测减少了临时聊天数据的数据库操作。RRF 处理的规模仍只有最多 20 个候选，删掉嵌套 Map 的主要收益是数据可追踪和可维护性。

应用接管了工作流和状态机，因此生命周期代码与维护成本增加。通用框架的聚合和记忆扩展点适合快速装配。当前项目用自己的类型表达版本、两路分数、实际注入资料和取消终态，调用链可以直接追到每个业务决策。

本次用假上游验证协议、状态、取消及可解释性。真实千问回答质量和实际部署下的首字延迟、吞吐、资源峰值还需要同一数据集和负载做 A/B，当前证据支持功能和韧性方面的改进。

## 验收范围

使用 JDK 21、项目 Maven 和 Reactor 3.7.11。MySQL 8.4.11 的新库初始化、旧库增量迁移与 SSE 联调在服务器上单独创建的临时测试库执行。测试不依赖用户的百炼密钥。既有项目数据库使用 README 的增量脚本升级。

2026-11-10 全量 Maven 测试通过 27 项，包含 8 项 MySQL 和嵌入式 Tomcat 集成测试。覆盖并发幂等、同会话行锁、READY 超期、SSE 断线、慢订阅者、检查点和迁移重复执行。假模型、假 ES 的本地网络测试还验证了缺少终止标记、响应头前取消、ES 版本过滤和连接关闭。原有上传、文档解析测试一起通过。

浏览器验证了正常完成、首字前停止、输出中停止、刷新恢复、模型中断展示和旧 /chat/send 完成标记。单独验证了 SSE 解析器处理逐字节 UTF-8 拆包、CRLF、多行 data 和注释心跳。

常规测试命令为 `mvn -B -o -Dmaven.repo.local=D:/maven-repository test`。MySQL 集成测试从 `CHAT_IT_JDBC`、`CHAT_IT_LEGACY_JDBC`、`CHAT_IT_USER` 和 `CHAT_IT_PASSWORD` 读取隔离环境。两个测试库都须为空，库名以 `ke_chat_test_` 开头，旧结构迁移测试库名以 `legacy` 结尾。用完可删除这两个测试库及其独立账号。

使用单个 Java 实例持有活动轮次。事件接口在 Servlet 处理请求时执行 READY 准入，以返回真实 409/429；上游生成仍由第一次流订阅启动。显式取消 READY 通过条件 SQL 直接提交。已启动的轮次通过 FINALIZING 协调，暂时无法确认提交时客户端用状态查询处理。

集成并发场景按 2 个活动轮次加 1 个额外请求验证。生产默认 8 个活动轮次下的资源峰值、真实慢速 TCP 客户端长期压测、数据库提交成功但 JDBC 报超时的故障注入和强杀进程后的恢复仍待实测。
