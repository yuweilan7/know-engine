# 聊天历史快照

每个在线轮次开始时，`DatabaseChatMemoryStore.loadHistory` 根据本轮的用户消息 ID 在 MySQL 读取一次历史。意图识别、问题改写和回答生成都复用这份快照。意图识别的 LangChain4j 临时记忆在分类结束后丢弃。

1. 创建轮次时，用户消息、助手占位和 `chat_run` 在同一事务写入。会话归属一致且没有活动轮次才能创建。
2. 历史查询按消息自增 ID 从本轮向前读取。新消息只选 `COMPLETED` 轮次，再按 `run_id` 配对用户和助手。取消、失败或超时的文本仍可从会话页面查看。
3. 旧消息的 `run_id` 为 NULL。按顺序将相邻的用户问题和非空助手回答配对。空占位会结束这次配对，避免把它前面的问题误配到下一次回答。
4. 最近五个完整问答对按时间顺序交给编排器。`PromptBudget` 从最近一对开始保留，空间不足时整轮裁剪。RAG 生成把剩余输入空间留给实际选中的资料。
5. 流中检查点保存已收到的文本。终态和最终答案在同一事务提交，后续轮次才能把新完成的问答加入历史。

MySQL 是聊天历史的读取入口。Redis 继续供应用其他功能使用。检查点和终态 SQL 的写入路径见 `ChatRunStore`，SSE 与取消入口见 `ChatRunService`。
